Perforce Puppet added to CISA KEV catalog

Active exploitation of a widely used infrastructure-as-code platform increases third-party risk because compromised Puppet servers can control enterprise configuration. The accountable owner should confirm supplier dependencies, assurance evidence, and escalation contacts for Perforce Puppet.

Supplier risk owner

02

High priorityAccess management

Java4Shell flaw enables pre-auth RCE in Keycloak

Pre-authentication remote code execution in identity and access management tools such as Keycloak weakens access management by bypassing authentication boundaries. The accountable owner should review privileged access, authentication coverage, and session revocation evidence for affected applications.

Accountable owner
Identity and access owner
Evidence to request
Access scope, authentication coverage, session revocation and a permission-test result.
Decision trigger
If a permission gap is reproduced, assign a control correction and verify it; otherwise retain the test evidence.
Reference controls
ISO/IEC 27001:2022 A.5.15 (access control), A.5.18 (access rights), A.8.2 (privileged access rights); NIST CSF 2.0 PR.AA (identity management, authentication and access control)

Medium priorityVulnerability management

NGINX HTTP/2 support enables unauthenticated code execution

A decade-old vulnerability in a ubiquitous web server component weakens vulnerability management by exposing unpatched servers to unauthenticated remote code execution. The accountable owner should identify affected assets, verify remediation status, and document any exceptions.

Vulnerability and asset owners
Evidence to request
Affected-asset inventory, installed versions, remediation status and an exception owner.
Decision trigger

Reference controls

04

Medium priorityData protection

Low-privilege database accounts enable server code execution

Memory-corruption bugs in database engines allow low-privilege accounts to execute code on the server, threatening data protection for sensitive information stored in PostgreSQL, MySQL, and Oracle. The accountable owner should review sensitive-data access restrictions, audit logs, and exposure assessments.

Accountable owner
Data and privacy owners
Evidence to request
Data inventory, access restrictions, audit logs and a documented exposure assessment.
Decision trigger
If relevant data is exposed to the reported access path, decide which protection or access change is needed.
Reference controls
ISO/IEC 27001:2022 A.5.34 (privacy and protection of PII), A.8.12 (data leakage prevention), A.8.24 (use of cryptography); NIST CSF 2.0 PR.DS (data security)

Credential theft and impersonation chains enable lateral movement that evades standard detection, weakening monitoring and detection coverage. The accountable owner should review log coverage, detection tests, alert routing, and investigation ownership for identity-based anomalies.

Detection and monitoring owner
