Key messages

  1. Active exploitation of critical vulnerabilities in the binary-parser library, ConnectWise ScreenConnect, and Azure API Management Classic tiers, combined with industrial serial gateways broadcasting insufficient authentication, demonstrates systemic gaps in vulnerability management and access controls across software supply chains and operational technology. Control owners must verify asset inventory coverage, patch deployment, and authentication enforcement for exposed components. [1]; [2]; [5]; [10]

  2. The KEPCO breach exposing customer, employee, and contractor data, alongside a new framework for ransomware actor attribution, underscores persistent data protection deficiencies and evolving incident response capabilities. Data protection owners should assess exposure scope and notification readiness, while incident response leads should evaluate integration of attribution advances into containment procedures. [7]; [12]

High priorityVulnerability management

binary-parser library weakens code injection defenses

The vulnerability in a widely used library enables arbitrary code execution when parser definitions are attacker-controlled, undermining vulnerability management assurance. The vulnerable asset owner must confirm affected deployments and remediation status.

Accountable owner
Vulnerability and asset owners
Evidence to request
Affected-asset inventory, installed versions, remediation status and an exception owner.
Decision trigger
If applicability is confirmed, decide on remediation or a documented exception; otherwise record why the finding does not apply.
Reference controls

02

High priorityThird-party risk

ConnectWise ScreenConnect exposes MSP technician hosts

Active exploitation of a patched flaw in MSP remote access software indicates supply chain risk from unpatched vendor components. The supplier risk owner must verify patch deployment across MSP connections and assess technician access controls.

Accountable owner
Supplier risk owner
Evidence to request
Supplier access scope, control responsibilities and evidence of remediation assurance.
Decision trigger
If the supplier dependency exists and assurance is insufficient, request evidence or escalate the assurance gap to its owner.
Reference controls
ISO/IEC 27001:2022 A.5.19 (supplier relationships), A.5.21 (ICT supply chain), A.5.22 (monitoring and review of supplier services); NIST CSF 2.0 GV.SC (cybersecurity supply chain risk management)
03

Medium priorityAccess management

Critical OT access devices broadcast authentication status

Industrial gateways revealing absent authentication weaken access management assurance for operational technology. The identity and access owner must verify authentication coverage on all OT access devices and enforce mandatory authentication.

Accountable owner
Identity and access owner
Evidence to request
Access scope, authentication coverage, session revocation and a permission-test result.
Decision trigger
If a permission gap is reproduced, assign a control correction and verify it; otherwise retain the test evidence.
Reference controls
ISO/IEC 27001:2022 A.5.15 (access control), A.5.18 (access rights), A.8.2 (privileged access rights); NIST CSF 2.0 PR.AA (identity management, authentication and access control)
04

High priorityMonitoring and detection

Azure API Management Classic tiers leak API credentials

Exploited cloud vulnerability enabling credential theft from API management tiers demonstrates monitoring gaps for credential misuse. The detection owner must verify telemetry coverage for anomalous API credential access and alerting on credential exfiltration.

Accountable owner
Detection and monitoring owner
Evidence to request
Log coverage, a detection test, alert routing and investigation ownership.
Decision trigger
If a detection test fails, assign the coverage or routing correction and repeat the test.
Reference controls
ISO/IEC 27001:2022 A.8.15 (logging), A.8.16 (monitoring activities); NIST CSF 2.0 DE.CM (continuous monitoring), DE.AE (adverse event analysis)
05

High priorityData protection

Korea Electric Power Corporation exposes customer employee data

Breach of a national utility exposes sensitive personal data, indicating data protection control failures. The data protection owner must assess the scope of exposed records, regulatory notification obligations, and remedial access restrictions.

Accountable owner
Data and privacy owners
Evidence to request
Data inventory, access restrictions, audit logs and a documented exposure assessment.
Decision trigger
If relevant data is exposed to the reported access path, decide which protection or access change is needed.
Reference controls
ISO/IEC 27001:2022 A.5.34 (privacy and protection of PII), A.8.12 (data leakage prevention), A.8.24 (use of cryptography); NIST CSF 2.0 PR.DS (data security)
06

Medium priorityIncident response

new framework enables ransomware actor tracing

Emerging attribution framework improves ransomware actor tracing, enhancing incident response evidence collection. The incident response lead should evaluate framework integration into response procedures and evidence preservation workflows.

Accountable owner
Incident response lead
Evidence to request
Containment responsibilities, retained logs and the most recent response exercise.
Decision trigger
If an exercise exposes an ownership or evidence gap, assign a response-plan correction and retest it.
Reference controls
ISO/IEC 27001:2022 A.5.24 (incident management planning and preparation), A.5.26 (response to information security incidents); NIST CSF 2.0 RS.MA (incident management), RS.MI (incident mitigation)
